Les trois modes de capture

additifs, non destructifs : le chemin statique gelé reste byte-identique

D1
voyait pas : le mouvement

Motion capture

Séquence multi-frames (strip) des entités de rue livrées : la traversée du livreur (courier) et le QTE cinématique — le push de zoom sur l'ancre, puis le tell G4 COVERED→PEEKING. Mode « play » dégelé (__MUF_PLAY__), audio muet, seed épinglé ; garde de seam non-vacuité via __MUF_STATE__.

D2
voyait pas : la boucle interactive

Play-through scripté

Injecte un vrai input dans le canvas, lit l'état LIVE via le seam, assert des deltas exacts : belliard PANIC (un tir en ZOOMING → énergie −6, score inchangé) et vitry ACCOMPLICE (sans tirer, drain −8 par tir de l'accomplice, captorHp intact — invariant P3-ACC). La boucle complète input → render → state → HUD.

D3
voyait pas : les régressions gelées

Golden-screenshot

Pixel-diff de stalingrad et vitry contre des goldens PNG committés. Garantit au niveau visuel le « byte-for-byte unchanged for the same seed ». Un diff hors tolérance rougit le run.

La loi : le seam est la loi

Le harness lit l'état de jeu uniquement via un seam sanctionné : un getter read-only exposé sur window (clone gelé de l'état + HUD), bridgé dans le seul fichier autorisé src/hooks/useGameLoop.ts.

Boundary rule + DIP : le harness dépend de l'abstraction, jamais d'un import d'un système de jeu (src/game/**) ni des internals de rendu (src/render/**) ; il porte zéro règle de jeu. TDD : les assertions D2 sont écrites en premier, vérifiées à vide, puis vertes contre le build ; un harness rouge bloque le merge.
